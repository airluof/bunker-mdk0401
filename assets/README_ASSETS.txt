БИБЛИОТЕКА ИЛЛЮСТРАЦИЙ «БУНКЕР» — МДК.04.01
================================================

Состав:
- 180 PNG-иллюстраций, 6 категорий по 30 файлов.
- manifest.json — полный машинно-читаемый каталог.
- manifest.csv — тот же каталог в табличном формате.
- QA_REPORT.json — технический отчёт проверки.
- README_ASSETS.txt — эта инструкция.

Структура изображений:
assets/cards/roles/
assets/cards/skills/
assets/cards/baggage/
assets/cards/vulnerabilities/
assets/cards/crises/
assets/cards/actions/

Идентификаторы:
role_01 ... role_30
skill_01 ... skill_30

vulnerability_01 ... vulnerability_30
crisis_01 ... crisis_30
action_01 ... action_30

ВАЖНОЕ ПРАВИЛО ИНТЕГРАЦИИ:
Используйте card_id как стабильный идентификатор карточки.
Не пытайтесь восстанавливать оригинальные названия из имён файлов.
В manifest.json / manifest.csv поле original_title сохраняет название из исходной книги Excel.
Поле file_name содержит фактическое имя PNG, экспортированное из Figma.
Некоторые символы в именах файлов были заменены Figma для совместимости с файловой системой
(например, косая черта может быть заменена пробелом, а знак > — подчёркиванием).
Это не изменение оригинального названия карточки. В интерфейсе нужно отображать original_title.

Пример:
card_id: baggage_28
original_title: Криптошлюз ГОСТ (Континент / ViPNet)
file_name: baggage_28 — [Криптошлюз ГОСТ (Континент ViPNet)].png

Пример использования в React:
<img src="/assets/cards/baggage/ИМЯ_ФАЙЛА.png" alt={card.original_title} />

Предпочтительный способ:
1. Загружать/импортировать manifest.json при сборке приложения.
2. Находить изображение по card_id.
3. Отображать оригинальное название и описание из проверенного каталога карточек.
4. Для мобильных и настольных экранов использовать один исходный PNG с object-fit: cover
   или object-fit: contain в зависимости от согласованного дизайна карточки.

Изображения:
- Формат: PNG
- Размер: 1200 × 1600 px
- Оригинальные PNG включены без изменения содержимого.
