# Цифровые правила карт Действий — дополнение v2

**Дата:** 09.11.2026  
**Ветка:** `work/neurotech-redesign-and-game-audit`  
**Назначение:** описать однозначные цифровые процедуры для карт, не меняя названия и исходные описания карточек.

Оригинальные тексты и изображения из книги `Bunker_MDK0401_Materials.xlsx` не переписываются. Правила ниже — конкретизация для онлайн-версии. Они не должны восприниматься как дословная часть исходной настольной колоды.

## Общие правила применения

- Карта Действия применяется владельцем не более одного раза за партию. После успешного применения она открывается всем игрокам.
- Сервер проверяет фазу, владельца карты, цель и наличие необходимых карт. Если условие не выполнено, действие не расходуется.
- Все изменения карт выполняются одной серверной транзакцией: либо эффект применяется целиком, либо состояние партии не меняется.
- Если у игрока несколько карт Багажа, для эффектов №3, №12 и №16 используется самая старая карта: сначала по времени получения (`created_at`), затем по ID экземпляра. Это техническое правило устраняет конфликт с дополнительным Багажом от карт №16 и №24.
- Карты Ролей, Навыков, Багажа и Уязвимостей сами по себе не дают неописанных числовых бонусов. Связи этих карт с Кризисами остаются подсказками для аргументации.

## Эффекты, полностью автоматизированные

### №2 — Rollback

**Когда:** только в фазе открытого голосования и до того, как ведущий подведёт итоги.

**Процедура:** владелец применяет карту. Уже поданные голоса остаются в журнале, но результат голосования этого раунда отменяется: никто не выбывает. Ведущий может завершить раунд и перейти дальше.

Rollback не возвращает карты, не отменяет уже выполненные действия и не откатывает предыдущие раунды. Он отменяет именно результат текущего голосования.

### №5 — gpupdate /force

**Когда:** в фазе брифинга или голосования.

**Процедура:** владелец выбирает другого живого игрока. Сервер случайно выбирает одну из его закрытых карт любой категории и публично раскрывает её.

Если у цели не осталось закрытых карт, действие не расходуется. Категория не выбирается атакующим, поскольку оригинал не задаёт категорию; случайный выбор — нейтральная цифровая процедура.

### №7 — Право Вето Архитектора

**Когда:** только во время голосования, до подведения итогов.

При применении владелец выбирает **один** из двух режимов, напечатанных на карточке:

1. **Двойной голос.** Голос владельца учитывается как два голоса этого раунда.
2. **Спасение при равенстве.** Если владелец попадает в группу игроков с максимальным одинаковым количеством голосов, он исключается из списка кандидатов на изгнание. Если после этого остаётся несколько кандидатов с равным результатом, обычное правило ничьей продолжает действовать.

Режим выбирается при применении карты и не может быть изменён после подведения итогов. Это не два одновременных эффекта.

### №9 — Песочница безопасности

**Когда:** в течение активного раунда до перехода к следующему раунду.

**Процедура:** владелец выбирает себя или другого живого игрока. До завершения этого раунда выбранный участник защищён от направленных действий:

- gpupdate /force — принудительное раскрытие карты;
- vMotion — обмен Ролями;
- списание Багажа;
- Clone VM — копирование Навыка;
- Session Hijacking — обмен Уязвимостями;
- Memory Dump — просмотр закрытых карт.

Глобальные действия, действующие на всех участников или на игровое поле, защита не отменяет. Карта не отменяет эффекты, которые уже успели примениться. Автоматические штрафы от Уязвимостей пока не реализованы, поэтому защита не может отключать такие штрафы; карта Safe Boot №25 остаётся отключённой.

### №14 — Клонирование виртуальной машины

**Кто считается соседом:** ближайший живой участник справа или слева в круговом порядке игроков комнаты. Порядок фиксируется временем входа в комнату; после последнего игрока следует первый.

**Процедура:** владелец выбирает одного из двух соседей. Сервер берёт самую старую карту Навыка выбранного участника, раскрывает исходный Навык и создаёт открытую копию у владельца действия.

Копия остаётся у владельца до конца партии. Исходная карта остаётся у соседа. Если у соседа нет Навыка, эффект не применяется и карта не расходуется. Копируется сама карта Навыка, а не отдельный числовой эффект: универсальных числовых эффектов у Навыков исходные правила не задают.

### №29 — Factory Reset

**Процедура:** после применения карта Действия остаётся открытой и считается использованной. Все карты владельца четырёх основных категорий — Роль, Навык, Багаж и Уязвимость — отправляются в сброс, включая дополнительные экземпляры, полученные другими действиями.

Затем владелец получает по одной новой закрытой карте из каждой из этих четырёх колод. Если хотя бы в одной колоде нет карты, транзакция отменяется полностью: старые карты не теряются, а действие не расходуется.

## Уточнения к ранее включённым действиям

- **№3 Hot-Swap:** при замене используется самая старая карта Багажа владельца; при выборе изгнанного участника — самая старая карта его Багажа. При обмене каждый получает карту другого.
- **№12 Списание:** у выбранного живого участника сбрасывается самая старая карта Багажа. Наличие второго предмета не блокирует эффект.
- **№16 Конфискация:** владелец получает самую старую карту Багажа выбранного выбывшего участника. Статус выбывшего не меняется.

## Карты, которые пока не считаются полностью автоматизированными

| Карта | Статус | Почему |
|---|---|---|
| №1 Внеплановый аудит компетенций | Нужна ручная процедура | Вопрос по Роли/Навыку и оценка ответа требуют нейтрального проверяющего; нужно зафиксировать, как бонусный голос попадает в итог |
| №13 ПСИ | Нужна ручная процедура | Нужны ведущий/судья, критерии точности решения и срок иммунитета |
| №19 Балансировка нагрузки | Нужна уточнённая процедура | Не определено, кто считается похожим игроком и как перераспределять нечётное количество голосов |
| №22 Блокировка учётной записи | Не реализована | В партии нет отдельной процедуры ввода паролей и учёта трёх ошибок |
| №23 Отказоустойчивая пара | Не реализована | Нужны правила совместного подсчёта голосов, мест и изгнания пары |
| №26 Escalation to L2 | Нужна процедура преподавателя | В онлайн-комнате нет отдельной роли/канала преподавателя для запроса и выдачи подсказки |
| №27 Дедупликация персонала | Не реализована | Роли раздаются без дубликатов, поэтому два одинаковых экземпляра не появляются |
| №30 Подписание Акта ПЭ | Нужен финальный аудит | Нет утверждённой рубрики, определения ошибки и автоматического механизма права на одну ошибку |
| №21 Workaround | Отключена | Финальный аудит пока не умеет исключать выбранный Кризис из проверки |
| №25 Safe Boot | Отключена | Уязвимости ещё не имеют формализованных автоматических эффектов, которые можно отключить |

## Текущий статус карт Действий

- **20** эффектов включены и имеют серверную обработку.
- **8** требуют дополнительного правила или ручной процедуры.
- **2** временно отключены, потому что текущая система не может выполнить заявленный эффект.

Это не означает, что все игровые правила уже завершены: остаются вопросы основного цикла, финального аудита, отключений и нескольких карт Действий.
