## Что есть в рабочей ветке

- Онлайн-комнаты: анонимная авторизация, создание, вход по пятисимвольному коду из `A–Z` и `0–9`, настройки 8–16 участников, тестовый режим с ботами. Старые 32-символьные коды остаются совместимыми.
- Серверный игровой цикл: раздача пяти карт, раскрытие по раундам, минутный таймер, голосование, подсчёт, исключение и кризисы раундов 2 и 4.
- Серверная приватная рука: личные карты возвращаются владельцу; публичные карты появляются после раскрытия.
- 14 эффектов действий полностью включены. Два частичных эффекта (`action_21`, `action_25`) отключены до завершения логики; ещё 14 карточек остаются `draft` до уточнения правил.
- Финальный план хранится в Supabase как одна общая запись.
- Миграция 012 добавляет heartbeat, перехват управления после 90 секунд отсутствия heartbeat, автоматическую передачу технического управления при исключении ведущего и доступ к финальному плану для любого выжившего участника.
- Восстановленный тёмный дизайн сохранён. Шапка, логотип, иконки навигации и блок приглашения получили дополнительное выравнивание для ПК и телефонов.

## Что именно проверяют автоматические проверки

GitHub Actions:
1. проверяет исходный каталог: 180 карт, 30 в каждой категории;
2. проверяет структуру базовой схемы и RLS;
3. проверяет соответствие обработчиков карточек исходному каталогу;
4. проверяет наличие runtime-контрактов heartbeat, takeover и общего финального плана;
5. проверяет отсутствие service_role ключа во frontend;
6. выполняет TypeScript-проверку и production build.

Эти проверки подтверждают структуру исходников и сборку. Они **не доказывают**, что SQL был применён в конкретном Supabase-проекте и что сетевой сценарий прошёл на реальных клиентах.

## Как проверить настоящий Supabase

Используй тот проект Supabase, URL которого указан в `.env.local` для игры. Не выбирай другой проект только потому, что он появился в списке подключённых проектов.

PowerShell из корня репозитория:

```powershell
$env:SUPABASE_URL = "https://YOUR_PROJECT_ID.supabase.co"
$env:SUPABASE_ANON_KEY = "YOUR_ANON_OR_PUBLISHABLE_KEY"
npm run db:smoke
Remove-Item Env:SUPABASE_URL
Remove-Item Env:SUPABASE_ANON_KEY
```

Smoke-тест создаёт тестовую комнату, заполняет недостающие места ботами, запускает партию, проверяет пять личных карт и один кризис, раскрывает карту и переводит фазу в брифинг. После завершения тест пытается закрыть тестовую комнату.

Не используй `service_role` ключ для этого теста. Тест использует только анонимную авторизацию и публичный ключ.

## Ограничения, которые нельзя закрыть без решения по правилам

- Обычная ничья возвращает `VOTE_TIE_NEEDS_RULE`. Случайный выбор разрешён только в тестовом режиме. Нельзя выбрать правило ничьей без владельца игры.
- Не согласованы правила пропуска/ожидания отключившегося игрока, поэтому heartbeat восстанавливает присутствие и позволяет передать техническое управление, но не подменяет голос и не исключает отсутствующего участника.
- 14 карт действий остаются в `draft` из-за неуточнённых правил.
- `action_21` и `action_25` временно отключены: Workaround пока не влияет на проверку финального плана, а Safe Boot не может отключать неформализованные эффекты Уязвимостей.
- Карточный просмотр показывает тематические связи всех 180 карт. Эти связи не дают автоматических бонусов и не заменяют согласование игровых правил.
- Финальный план — общее текстовое поле с последним сохранением. Это не полноценный одновременный редактор.
- Публичный GitHub-репозиторий содержит исходные описания всех карточек и доступный каталог. Закрытая таблица Supabase не делает тексты карточек секретными при текущей модели публикации.

## Приёмочные критерии

Проект можно считать готовым к публичной приёмке только после:
- успешного CI на актуальном commit;
- применения всех миграций к тому Supabase-проекту, который использует Preview/production;
- успешного runtime smoke test;
- двух- и многопользовательской проверки обычной и тестовой комнаты;
- проверки failover ведущего и сохранения финального плана после исключения ведущего;
- проверки поведения при переподключении;
- согласования открытых игровых правил или явного сохранения соответствующих функций выключенными;
- проверки UI на ПК и мобильных размерах.
