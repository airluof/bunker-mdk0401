# Настройка Supabase для «Бункера»

Этот документ относится к первой серверной заготовке в рабочей ветке проекта.

## Что добавлено

- SQL-миграции `202611040001_initial_multiplayer_schema.sql` и `202611040002_room_lobby_settings.sql`.
- Серверные таблицы комнат, участников, сессий, публичного состояния, каталога, экземпляров карточек, голосов, событий, финальных отправок и квитанций команд.
- RLS для чтения данных комнаты только её действующими участниками.
- Закрытая таблица card_catalog: обычный клиент не получает к ней прямой доступ. Первичный ключ включает card_id и catalog_version, чтобы сохранять исторические версии набора для партий.
- RPC: api_create_room, api_join_room, api_get_room_snapshot и api_start_game.
- Клиентские обёртки в src/services/onlineRooms.ts.
- Локальный административный импортёр scripts/import-cards-to-supabase.mjs.

## До первого запуска

1. Создай проект Supabase. Регион выбирай ближе к игрокам, учитывая реальные сетевые тесты и требования к данным.
2. В настройках Authentication включи Anonymous Sign-Ins.
3. Выполни SQL-миграции из папки `supabase/migrations` строго по порядку имён через Supabase SQL Editor либо Supabase CLI. Если первая миграция уже применена, выполни только следующую новую миграцию.
4. Убедись, что каждая миграция завершилась без ошибок.
5. Выполни импорт каталога с локального компьютера владельца.

Для создания комнаты, подключения по коду, получения снимка и подготовки старта доступны RPC api_create_room, api_join_room, api_get_room_snapshot и api_start_game. Для выхода из лобби/архивной комнаты и закрытия ещё не начатой комнаты добавлены api_leave_room и api_close_room. Код приглашения — 32 шестнадцатеричных символа (128 бит случайности); в базе хранится только его SHA-256.

## Импорт 180 карточек

Скрипт читает локальный assets/manifest.json (путь можно переопределить через BUNKER_CARD_MANIFEST_PATH), проверяет 180 уникальных ID и ровно 30 карт в каждой из шести категорий, затем загружает данные в закрытую таблицу card_catalog. Для dry-run ключ Supabase не требуется.

PowerShell из корня проекта:

```powershell
npm run db:import-cards -- --dry-run

$env:SUPABASE_URL = "https://YOUR_PROJECT_ID.supabase.co"
$env:SUPABASE_SERVICE_ROLE_KEY = "YOUR_SERVICE_ROLE_KEY"
npm run db:import-cards
Remove-Item Env:SUPABASE_SERVICE_ROLE_KEY
Remove-Item Env:SUPABASE_URL
```

Для первого шага можно использовать --dry-run: он проверяет локальный манифест, не отправляя данные. Структурную проверку миграции без подключения к Supabase запускает `npm run db:validate-migration`; она проверяет число таблиц и RPC, наличие RLS, баланс SQL-блоков, invite hashing и отсутствие прямых grants роли anon.

**Ключ service_role является секретом.** Не добавляй его в .env.local, VITE_*, GitHub Actions, React-код или Git. Используй его только в локальном PowerShell-сеансе для импорта. Не отправляй ключ в переписке.

## Переменные frontend

Скопируй `.env.example` в `.env.local` и укажи только публичные параметры:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY
```

Публичный anon/publishable key можно использовать в браузере, потому что доступ ограничивается RLS и RPC. Никогда не указывай service_role key в переменной с префиксом VITE_.

## Ограничения текущей итерации

- Главная страница, верхняя навигация, онлайн-лобби, каталог и карточки оформлены в стиле «Журнал инцидента». Онлайн-лобби показывает только реальных участников комнаты. Создатель может менять максимальный состав от 8 до 16 игроков; настройка хранится на сервере и обновляется у участников через Realtime. Для онлайн-комнаты доступен экран ожидания; реальный игровой стол пока не подключён.
- Серверный движок раскрытия карт, голосования, переходов фаз, эффектов действий и финального аудита пока не реализован.
- Условие старта сейчас задано как 8–16 активных участников (по текущему ограничению проекта).
- Процедуры, отмеченные как требующие утверждения в docs/02_Game_System.md, намеренно не автоматизированы.
- Realtime-подписки готовы на уровне клиента и публикации таблиц; события служат сигналом перечитать api_get_room_snapshot. При закрытии комнаты участники видят архивный статус и могут выйти.
- До подключения реального проекта Supabase нельзя считать схему применённой или мультиплеер работоспособным.

## Важное ограничение приватности каталога

Таблица card_catalog закрыта для обычных ролей anon/authenticated. Однако текущий публичный репозиторий всё ещё содержит исходные JSON-манифесты с текстами 180 карточек, а существующий frontend импортирует assets/manifest.json. Поэтому на этом этапе нельзя заявлять, что содержимое скрытых карточек защищено от игроков. Следующий обязательный этап — перевести UI на серверные RPC, затем убрать манифесты из актуального публичного дерева. Уже опубликованная история Git может сохранять старые версии файлов; удаление текущей копии не отменит прошлую публикацию.


## Публикация на GitHub Pages

В репозитории добавлен workflow `.github/workflows/deploy-pages.yml`. После объединения изменений в `main` он автоматически:
1. Установит зависимости Node.js.
2. Соберёт production-версию командой `npm run build`.
3. Опубликует папку `dist` через GitHub Pages.

Перед первой публикацией открой GitHub: **Settings → Pages → Build and deployment → Source** и выбери **GitHub Actions**. После этого проверь вкладку **Actions** и дождись успешного workflow Deploy to GitHub Pages.

Публикация из текущей рабочей ветки не запускается автоматически: workflow предназначен для `main`, чтобы незавершённые изменения не заменили рабочий сайт. CI для Pull Request отдельно проверяет сборку.

## Проверки и ещё не выполненные этапы

- Миграция и RPC пока не запускались в настоящем проекте Supabase; SQL должен быть применён владельцем проекта и проверен через SQL Editor.
- GitHub Actions добавлен для проверки структуры каталога (dry-run), статической структуры Supabase-миграции, попадания service_role в frontend, whitespace diff, TypeScript и production build. Один CI run успешно выполнил установку зависимостей, проверку 180 карт, TypeScript и production-сборку на head-коммите 59ef05f; более поздние изменения дизайна ожидают отдельного CI run. Локальная сборка в этой рабочей среде не запускалась.
- Нет серверных RPC для раскрытия карт, перехода фаз, таймера, голосования, исключения участников, эффектов действий и финального аудита. Онлайн-комната пока заканчивается лобби.
- Полный текстовый каталог всё ещё присутствует в публичных JSON-манифестах репозитория, и текущий локальный каталог импортирует его в клиент. До миграции всех экранов на серверный каталог нельзя считать тексты скрытых карт защищёнными.
- При закрытии комнаты участники остаются в архивной комнате до явного выхода, чтобы успеть увидеть уведомление и покинуть комнату. Выход из партии в активном состоянии намеренно заблокирован до утверждения Q-24.
