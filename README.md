# Bunker — МДК.04.01

Браузерная многопользовательская игра по предметной области МДК.04.01.

## Текущий статус

- Исходные правила и все 180 карточек зафиксированы в документации.
- Цифровая игровая модель спроектирована; часть процедур требует утверждения владельцем.
- Техническая архитектура: React + TypeScript + Vite, GitHub Pages и Supabase Free.
- Библиотека из 180 PNG размещена в `public/assets/cards/` (6 категорий по 30 изображений).
- В рабочей ветке реализован серверный игровой цикл: создание/вход в комнату, личная раздача, раскрытие карт, брифинг, голосование, исключение, кризисы и финальный план. Для работы необходимо применить все нужные SQL-миграции и импортировать каталог в Supabase.

## Категории карточек

## Структура визуальных ресурсов

PNG-файлы уже размещены в репозитории по пути:

```text
public/assets/cards/
  roles/
  skills/
  baggage/
  vulnerabilities/
  crises/
  actions/
  manifest.json
  manifest.csv
```

Манифест содержит стабильный `card_id`, оригинальное название карточки, экспортированное имя файла и относительный путь к изображению. Использовать `card_id` как основной ключ сопоставления. Не исправлять и не переименовывать экспортированные PNG автоматически.

## Важные ограничения

1. Не придумывать и не менять оригинальные игровые правила без утверждения владельца.
2. Не публиковать Supabase `service_role` key, пароли, токены и другие секреты.
3. Репозиторий публичный: исходники, документация и добавленные изображения доступны всем.
4. Не хранить персональные данные игроков в GitHub.
5. До реализации полной игровой логики согласовать открытые вопросы из документа 02.
6. 25 пользователей — ожидаемая суммарная одновременная нагрузка сайта, а не размер одного лобби. Размер одной комнаты — до 16 игроков.

## Разработка

Стек: React, TypeScript, Vite, Supabase PostgreSQL/RPC/RLS/Realtime. Автоматическая проверка карточек, секретов, TypeScript и production-сборки описана в `.github/workflows/ci.yml`. Для публикации после объединения в `main` подготовлен `.github/workflows/deploy-pages.yml`.

Серверный игровой цикл и 16 одобренных обработчиков карт действий реализованы в рабочей ветке. 14 действий остаются draft, а неоднозначные процедуры (включая ничью) не автоматизируются до утверждения. Публичные JSON-манифесты и документация раскрывают все 180 карточек; см. [05 — Настройка Supabase](docs/05_Supabase_Setup.md) и [06 — Текущий статус и тестирование](docs/06_Runtime_Test_Plan.md).
