# Бункер — МДК.04.01

Браузерная многопользовательская игра по предметной области МДК.04.01. Игроки собирают команду, раскрывают характеристики, обсуждают кризис, голосуют и готовят план восстановления инфраструктуры.

## Текущий статус · 9 ноября 2026

Проект находится в состоянии **функционального онлайн-прототипа / бета-версии**. Основной серверный игровой цикл реализован, но публичный релиз ещё нельзя считать полностью принятым: клиентская Auth-сессия, реальная партия в нескольких браузерах, мобильные устройства и нагрузка требуют отдельной проверки.

- Стек: React 19, TypeScript, Vite 6, Supabase PostgreSQL / Auth / RPC / Realtime.
- Рабочая ветка: `work/neurotech-redesign-and-game-audit`. Изменения пока не объединены в `main`; PR #1 остаётся Draft.
- Для целевого проекта Supabase на 6 ноября 2026 подтверждено применение миграций 001–020 без пропусков. Серверный игровой цикл проверялся транзакционными тестами с `ROLLBACK`.
- GitHub Actions выполняет проверки каталога, миграций, эффектов карточек, runtime-контрактов, секретов, TypeScript и production-сборки.
- Preview-развёртывания ветки выполняются через Vercel. Для `main` также оставлен workflow GitHub Pages.
- Последние изменения интерфейса сохраняют исходную тёмную дизайн-систему. Восстановление комнаты после перезагрузки теперь сохраняет код приглашения и позволяет повторить подключение после временной сетевой ошибки.

**До публичного релиза необходимо:** выполнить клиентский `npm run db:smoke` с публичным ключом, пройти полную партию в двух браузерах, проверить переподключение и передачу управления ведущего, протестировать мобильную вёрстку и провести нагрузочный тест.

## Карточки

В репозитории находится библиотека из 180 PNG: 6 категорий по 30 карточек.

| ID | Категория | Количество |
|---|---|---:|
| roles | Роли | 30 |
| skills | Навыки | 30 |
| baggage | Багаж | 30 |
| vulnerabilities | Уязвимости | 30 |
| crises | Кризисы | 30 |
| actions | Действия | 30 |

Основной ключ карточки — стабильный `card_id`. Манифесты находятся в `assets/manifest.json`, `assets/manifest.csv` и `public/assets/cards/`. Исходные названия и описания карточек не следует автоматически переименовывать или исправлять.

> Важно: каталог карточек открыт посетителям сайта, и тексты всех карточек доступны в публичном репозитории. Закрытой остаётся личная раздача игрока, а не содержание всей колоды.

## Игровая логика

- Обычная комната рассчитана на 8–16 реальных игроков.
- 25 пользователей — ориентир суммарной одновременной нагрузки сайта по всем комнатам, а не число игроков в одном лобби.
- В тестовой комнате можно заполнить свободные места ботами. Боты предназначены для технической проверки и не используют игровой ИИ.
- В цифровой версии игрок выбирает любую ещё не раскрытую карту; выбор скрыт до общего вскрытия при переходе к брифингу.
- Сервер хранит состояние партии, личные карты, голоса и общий финальный план.
- Полностью включены 14 эффектов карт действий. Два частичных эффекта временно отключены, ещё 14 карт действий остаются в статусе `draft` до уточнения правил.

Неоднозначные правила нельзя додумывать на стороне интерфейса или сервера. Открытые вопросы перечислены в `docs/02_Game_System.md` и `docs/06_Runtime_Test_Plan.md`.

## Структура проекта

- `src/components/` — интерфейс и игровые компоненты.
- `src/services/onlineRooms.ts` — клиентские вызовы серверных RPC и Realtime.
- `src/data/` — каталог карточек и пояснения к ним.
- `supabase/migrations/` — последовательность миграций базы.
- `supabase/seeds/` — загрузка каталога карточек.
- `scripts/` — импорт и автоматические проверки.
- `docs/` — правила, техническая спецификация и отчёты аудита.

## Загрузка карточек в Supabase

Для другого проекта сначала примени необходимые SQL-миграции, затем используй импортёр `scripts/import-cards-to-supabase.mjs`. Подробная последовательность и нужные переменные окружения описаны в [документе 05](docs/05_Supabase_Setup.md).

Для клиентских проверок используй только `SUPABASE_URL` и публичный `SUPABASE_ANON_KEY` / publishable key. Никогда не помещай `service_role` или secret key в frontend, GitHub или браузер.

## Разработка

Требуется Node.js 22 или совместимая актуальная версия Node.js.

```bash
npm install
npm run dev
```

Проверки перед публикацией:

```bash
npm run lint
npm run build
npm run db:import-cards -- --dry-run
npm run db:validate-migration
npm run db:validate-actions
npm run db:validate-runtime
```

Клиентский smoke-тест целевого Supabase запускается отдельно:

```bash
SUPABASE_URL="https://YOUR_PROJECT_ID.supabase.co" \
SUPABASE_ANON_KEY="YOUR_PUBLIC_KEY" \
npm run db:smoke
``

Не запускай тест против неизвестного проекта: он создаёт тестовую комнату и после завершения архивирует её, а не удаляет записи.
